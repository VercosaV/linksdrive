## Overview

MyDashboard is a local web application that combines two tools in a single interface:
- **VideoGet** – a video downloader (YouTube, Alura, any direct `.mp4` URL) powered by **yt‑dlp**.
- **MyLinks** – a link‑dashboard with sticky notes, persisted in **Firebase Firestore**.

The UI is a single‑page app (`index.html` + `script.js`) that runs completely in the browser, using:
- Firebase v8 SDK for Firestore access.
- Offline persistence (`db.enablePersistence`) + a manual localStorage cache for instant UI rendering and backup.
- Client‑side password protection built with PBKDF2 (salt + hash stored in localStorage).
- Utilities exposed on `window` for bulk import/export of links and duplicate removal.

A minimal Flask backend (`app.py`) is expected to expose the VideoGet API (download endpoints). The repository includes `requirements.txt` with `flask` and `yt‑dlp`, but the `app.py` file is currently missing from the tree.

## High‑Level Architecture

```
└─ MyDashboard (static front‑end)
   ├─ index.html          – main page, loads script.js and Firebase SDKs
   ├─ style.css           – UI styling (not shown here)
   ├─ script.js           – all client logic
   │   ├─ Firebase config & init
   │   ├─ Offline persistence + localStorage cache
   │   ├─ Auth (PBKDF2, stored in localStorage)
   │   ├─ Collections handling:
   │   │   • links   (CRUD, export, import, duplicate removal)
   │   │   • notes   (sticky notes, drag‑&‑drop ordering, folders)
   │   │   • folders (note organization)
   │   ├─ UI rendering helpers (categories, cards, notes grid)
   │   ├─ Modals (add link, edit category, change password, etc.)
   │   ├─ Utilities exposed on `window` for console usage
   │   └─ Event listeners (buttons, search, sort, view toggle)
   └─ app.py (Flask) – VideoGet API (download handling via yt‑dlp)
```

**Key design decisions**
- **Firestore offline persistence** drastically reduces read costs (Spark plan ≤ 50 k reads/day) by serving cached data on first load.
- **LocalStorage backup** provides a safety net when the remote DB is unreachable and enables a manual export.
- **Password protection** is performed entirely client‑side; the hash/salt are stored locally, so the password is not verified server‑side.
- **Export format**: JSON (re‑importable) plus a human‑readable TXT grouped by category.
- **Modular UI**: links view vs notes view toggled via `toggleView()`. Card size can be cycled (`small → medium → large`).
- **Import utilities** perform duplicate checks before adding to Firestore.
